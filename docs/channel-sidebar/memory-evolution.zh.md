# 记忆演化

打开 **Bot 私聊 → Channel sidebar → 记忆演化**。这里将当前未提交改动与 Git 历史分开。查看差异不会应用差异，也不会回退文件。

## 检查一次变更

1. 展开 **记忆演化**。
2. 在 **当前记忆** 中展开变更分组，点击文件，在中间区域查看 **未提交差异**。
3. 在 **提交历史** 中点击提交行，查看改动文件和 **提交差异**。
4. 查看后点击 **返回对话**。需要更早的历史时，点击 **加载更多提交**。

| 控件或标签                 | 含义                                                               |
| -------------------------- | ------------------------------------------------------------------ |
| 新记忆 / 已有记忆的更新    | 用更接近记忆用途的方式分组未提交改动。                             |
| 未暂存 / 已暂存 / 未跟踪   | 显示术语切为 **Git** 时，按对应 Git 状态分组。                     |
| HEAD 与分支标签            | Git 图中的当前提交与分支引用。                                     |
| 已记录 / Git 提交 / 待修复 | BotHarness 对 Git 历史的检查点标记，不代表文件作者或对内容的批准。 |

从 **Channel sidebar 显示设置 → 记忆演化 · 显示术语** 切换。它只改变标签与分组，不改仓库内容。

## 请求切换分支

在 **搜索分支** 中选择已有分支，再点击 **切换**。界面会向这个 Bot 的 Orchestrator 发送请求；只选下拉项不会检出分支。等待 Bot 报告结果，再核对显示的分支与当前文件。Git 因未完成改动而拒绝时，应保留改动，查看 Bot 的说明。

在提交差异中，**从该记忆节点新建并切换分支** 会打开新分支名称输入框。**创建并切换** 同样发送 Bot 请求；它从所选提交创建分支，不会撤销原分支上的后续提交。Bot 完成后，再核对操作结果和文件。

## 恢复检查点

**恢复检查点** 保存观察到的分支、HEAD、暂存区与工作树。来源说明 BotHarness 在何时观察或执行了操作，不代表 Git 文件作者。

只有确实要恢复该状态时，才选择检查点；核对确认提示中的分支与提交，再点击 **备份并恢复**。恢复会备份操作前的仓库，并显示备份位置。它会改变当前记忆，所以与日常读取、分支请求分开处理。**修复记忆** 状态也有独立的确认与备份流程。
