# Computer runtime contracts

This page preserves Computer implementation constraints formerly carried by source comments. The current architecture and accepted decisions remain in [the living architecture](botharness-architecture.md) and ADR-0050, ADR-0051, ADR-0052, ADR-0055, ADR-0058, ADR-0062, ADR-0079, ADR-0080, and ADR-0082. The viewer behavior also follows the accepted work in PR [#217](https://github.com/BotHarness/BotHarness/pull/217) and [#222](https://github.com/BotHarness/BotHarness/pull/222). This page describes the current implementation; changing a durable boundary requires an ADR and an architecture update.

## Provider and authority

- `packages/computer/src/service.ts` reserves one Computer provider slot. Its disposer releases only the registration it owns.
- `packages/computer/src/providers/docker.ts` runs one local Linux desktop container. Docker exposes its web endpoint on loopback; the Host authenticates and proxies the viewer. A named volume holds the desktop unless a Linux host directory is explicitly configured. A changed store or managed setting may recreate a stopped container, but must not tear down a running desktop. The UI must explain any pending store change. Desktop hardening is opt-in because disabling `exo-open` prevents normal application launch. Container startup, progress, resource limits, Chromium session restoration, and panel sizing are user-visible parts of this provider.
- `packages/computer/src/index.ts` authorizes start, stop, viewer, and transfer routes. Empty or invalid request bodies do not authorize start or stop. External commands receive paths as arguments, never shell text. Large archives stream through download and upload routes; upload writes a sidecar before rename so an interrupted transfer cannot replace a good archive. `packages/computer/src/transfer-tokens.ts` grants single-use transfers without storing tokens in settings.
- `packages/computer/src/viewer.ts` scrubs upstream framing headers for the same-origin iframe and forwards authenticated WebSocket upgrades. A failed upgrade closes the client socket.
- `packages/computer/src/tool/provider.ts` attaches the curated tools synchronously during Bot-owned agent setup, before the first prompt. A fallback catalog keeps those names present while the driver connects or the Computer is stopped; a warm catalog upgrades registrations in place. A stopped Computer returns a readable error. Authorization belongs to the session, access is checked on each call, and audit records omit typed text and screenshots. Failed diagnostics or audit sinks must not block an action.

## Viewer lifetime and interaction

- `packages/computer/src/client/index.tsx` keeps one keyed iframe for the whole Running lifetime. Opening fullscreen and collapsing it change that iframe's geometry; they do not create another viewer or WebSocket. Fullscreen starts in watch-only mode. Pointer and keyboard input need explicit opt-in for each fullscreen session. Only the toolbar collapse control exits fullscreen; Escape remains available to the remote desktop. A reconnect or document remount resets the liveness tracker. The hover Open control appears only after the stream is live.
- `packages/computer/src/client/frame-liveness.ts` samples the iframe's `#videoCanvas` size, Selkies `#status-display`, and a 16×16 pixel signature. Selkies can size a canvas before the first frame, so size alone is insufficient. Busy words are read only from the status element; unrelated sidebar text cannot mark the stream busy. Unreadable pixels degrade to the sized signal. The sampler and `packages/computer/src/client/viewer-events.ts` must never throw into the viewer.
- The first unsized document receives six misses (about five seconds) before Empty. A sized but busy stream receives thirty ticks to negotiate. A quiet, static, sized desktop becomes Live after four ticks and becomes Empty after 120 quiet ticks; a normal panel-clock repaint resets that long budget. After Live, three consecutive lost ticks trigger a remount. A document that never became Live gets at most three automatic reloads, then leaves manual Retry available. These budgets prevent boot negotiation and brief pauses from repeatedly restarting the viewer SPA.
- `packages/computer/src/client/viewer-state.ts` projects overlay, title, and action state with hysteresis. A normal container exit message is not shown as a raw machine error. `packages/computer/src/client/viewer-events.ts` sends bounded lifecycle diagnostics on transitions, never as a condition for rendering.

## Client settings and visual contract

- `packages/computer/src/client/settings-rows.tsx` uses the shared settings scope for runtime values. If a DSH scope write resolves but the Host refuses it, the refreshed snapshot rolling back is the refusal signal. An unset export directory falls back to the Host-resolved status path. Without a usable directory picker, the directory row is read-only. Browser archive bytes use XMLHttpRequest with a Blob body because the current transport mishandles `fetch` streaming bodies.
- `packages/computer/src/client/index.tsx` keeps its sidebar registry types structurally local so the Computer bundle remains self-contained. `BH` is the only table of DSH `--dsw-*` token aliases and audited light-theme fallbacks. `VIDEO_SURFACE` holds the fixed black/white stream letterbox and spinner colours in either theme. `packages/computer/test/client-tokens.test.ts` parses declarations to enforce that themed chrome uses `BH` and has no inline colours or legacy `--dsh-*` vars.

The relevant checks are under `packages/computer/test/`. Runtime verification should start an isolated DSH profile, open the Computer sidebar entry, exercise start, viewer Open/collapse, settings, and stop, and check for one iframe, a live stream, and no browser errors. A usable local Docker daemon and Computer image are prerequisites for the full desktop path.
