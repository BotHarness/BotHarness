# In-harness Client interaction contracts

The `@botharness/ui` bundle renders BotHarness inside the DSH Web Client. These contracts collect the behavior previously described beside the Client implementation. The [living architecture](botharness-architecture.md), [bridge contract](../client-bridge.md), and linked ADRs remain the authority for data ownership and product behavior. The [source policy](../agents/source-policy.md) keeps executable source free of explanatory comments.

## Host authority and Channel continuity

- The Client calls BotHarness commands through the shared DSH `/api` gateway in [`bridge.ts`](../../packages/client/src/client/bridge.ts). The API gateway owns that route; Client code does not register another interceptor. A stable Host error code drives handling, while the message is presentation text.
- `channelTimeline` establishes a durable revision before [`channel-live.ts`](../../packages/client/src/client/channel-live.ts) opens one authenticated SSE connection for the selected Channel. EventSource resumes from the last event ID. A stream gap triggers a Host reread. Process-local draft revisions and durable message revisions are separate.
- A visited Channel can retain its rendered view when the Human switches away and returns. Fresh timeline data merges only with a continuous cached window; an older window with a gap is not joined directly to the new tail. Only Host-committed messages advance the Human's durable read position. Local echoes and rejected sends remain process-local, and restoring a failed send returns its text and attachments to the composer for a new Human decision. See [ADR-0061](../adr/0061-channel-timeline-uses-opaque-cursors.md) and [`actions.ts`](../../packages/client/src/client/actions.ts).
- The composer in [`channel-composer.tsx`](../../packages/client/src/client/channel-composer.tsx) renders the owning conversation's draft and forwards send interaction. It does not become a second draft or activity authority. The current Channel switch lifecycle clears unsent composer text, reply target, and mention selections, and aborts outstanding uploads; cached timeline content does not retain an unsent composer draft. Expansion measures the compact width before collapsing so text near the wrap threshold cannot oscillate between layouts.

## Roster, sorting, and drag

- The Host `botharness_roster` domain owns pin, hide, section membership, and flat `topOrder`. The Client's [`roster.ts`](../../packages/client/src/client/roster.ts) and [`store.ts`](../../packages/client/src/client/store.ts) hold projections. Hiding a Channel removes it from navigation without changing placement. A Host without storage reports `storage-unavailable` and the roster stays read-only.
- Human sort preferences belong to the settings scope in [`bot-mode-prefs.ts`](../../packages/client/src/client/bot-mode-prefs.ts); they do not replace Host membership. A search filter changes visible rows only. Move and drag plans in [`roster-order.ts`](../../packages/client/src/client/roster-order.ts) use the unfiltered display order, so filtered-out Channels keep their positions and a Channel still has one section owner. Loose flat positions remain explicit in every sort mode; section member order may auto-sort until the Human freezes it.
- Drag markers in [`channel-drag.ts`](../../packages/client/src/client/channel-drag.ts) are temporary presentation state. Only a completed drop commits through the Host. A roster invalidation can precede the command response, so [`bot-sidebar.tsx`](../../packages/client/src/client/bot-sidebar.tsx) freezes the target display order before writes and restores the earlier preference when the Host rejects a move. After a committed mutation, the Client adopts the final Host snapshot; other windows treat `roster/changed` as an invalidation rather than as a replacement authority.
- The legacy browser arrangement migrates once to the Host only when that arrangement is empty. [`roster-migration.ts`](../../packages/client/src/client/roster-migration.ts) clears the legacy fields after Host writes, sort-mode remapping, and backup succeed; a failed attempt rolls back the new Host entries so the next load can retry. See [ADR-0031](../adr/0031-sidebar-organization-model.md) and [ADR-0034](../adr/0034-persistence-map-and-host-client-split.md).

## DSH shell and keyboard behavior

- DSH owns its Settings dialog and navigation. Its `settings.section` slot has no icon or section-navigation API, so BotHarness entry points open Bot Settings directly. Only DSH's own sections (Models, IM Bots) are still reached by scraping: [`bot-settings-open.ts`](../../packages/client/src/client/bot-settings-open.ts) finds the shell's dialog trigger by `aria-haspopup="dialog"` and a section by its current localized label. [`bot-icon-nav.ts`](../../packages/client/src/client/bot-icon-nav.ts) matches the same labeled cell before replacing the fallback gear with the Human-selected mark; failure to match leaves the native gear usable. The icon patch observes shell changes and disposes its inserted nodes when detached.
- Profile-wide settings live in Bot Settings ([ADR-0153](../adr/0153-bot-settings-is-a-botharness-owned-modal.md)), a headless DSH `Modal` mounted on `shell.overlay` by [`bot-settings.tsx`](../../packages/client/src/client/bot-settings.tsx). Its sidebar is projected from the `botharness.settings.section` ledger the way DSH's settings shell projects `settings.section`; the cache keys on both the ledger version and the locale revision because labels are locale thunks. A requested section that is not registered resolves to `general`, then to the first row. The last section asked for is kept only in memory, so a reload reopens at General. The card's CSS uses a doubled class so it outranks the primitive's single-class card rule without depending on stylesheet order. The section render result is cast at the package boundary because duplicate React type versions can disagree.
- DSH menus render into portals. The Channel and roster context menus refocus their placed list after positioning so keyboard focus can open submenus and arrow through entries. A section create or rename dialog selects its input, handles IME composition before Enter, and keeps focus on Cancel in destructive confirmation. These behaviors matter when replacing lifecycle hooks or changing the shell integration.
- Client HMR carries only the current Bot and Channel selection into the replacement Fiber. [`last-view.ts`](../../packages/client/src/client/last-view.ts) reads the prior document view once; HMR uses an in-document handoff. The optional Web development refresh in [`dev-client-refresh.ts`](../../packages/client/src/client/dev-client-refresh.ts) affects linked local bundles, not remote installations. See the [development bridge guide](../client-bridge.md).

## Generated art and attribution

Run `pnpm bot:icons` to regenerate [`bot-icon-assets.ts`](../../packages/client/src/client/bot-icon-assets.ts) from the PNGs under `packages/client/assets/bot/`. The generator emits comment-free source. The vendored Lucide `hash` header in [`hash-icon.tsx`](../../packages/client/src/client/hash-icon.tsx) remains with that file as required by its ISC notice; the [third-party notices](../../packages/client/THIRD_PARTY_NOTICES.md) also cover `hash`, the generic Bot glyph, and Blobatar.

## Interaction regression path

In an isolated DSH Profile, open Bot mode in both light and dark themes. Switch between two Channels and return to a visited Channel; check its cached timeline and that unsent composer text does not leak across the switch. Select a PersonaBot from the Roster, open the Channel sidebar controls, and exercise its context menu with pointer and keyboard. Test a failed send's draft recovery, a filtered roster move, and a Channel with new messages while the Human is reading older history. The existing composer, sidebar, and Channel reply/send-failure browser paths provide the starting automation; inspect browser console and failed requests as well as visible state.
