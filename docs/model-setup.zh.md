# 配置 API 与 Bot 模型

本页接续 [安装 DeepSeekBot](/zh/docs/installation)，使用 DSH **0.2.0-rc.1** 与公共包 **deepseekbot@0.1.0-alpha.1** 的实际界面。先配置 API 提供商，再为 Bot 选择模型；同一提供商可以供多个 Bot 使用。

## 1. 在 DSH 配置 Provider

点击左下角 **设置 → 模型**。已有提供商时点击其 **编辑**；新增时点击 **添加模型提供商**。

- **第三方模型提供商**：从内置目录选择提供商，填写该服务的 API 密钥，点击 **保存**。如果密钥由启动环境提供，输入框会显示只读提示，在启动环境中管理该密钥。
- **自定义模型 API**：用于兼容接口、中转站或自部署服务。填写下面的字段，添加至少一个模型，再点击 **创建提供商**。

![DSH 模型设置中的提供商目录与自定义设置，密钥未显示](/guides/settings/model-provider-catalog-zh.webp)

| 参数                         | 怎么填写 / 作用                                                                                    |
| ---------------------------- | -------------------------------------------------------------------------------------------------- |
| 提供商                       | 内置目录中的实际服务名称；决定适配器及默认模型目录。                                               |
| Provider ID                  | 自定义提供商的唯一标识，以小写字母开头，如 `acme-gateway`。模型路由使用此 ID，显示名称不能替代它。 |
| 显示名称                     | 你在界面中识别这个提供商的名称。                                                                   |
| API 地址                     | 服务商提供的接口基址，例如表单中的 `https://gateway.example/v1`；内置提供商留空时使用其默认地址。  |
| API 协议                     | 按接口选择 OpenAI Chat Completions、OpenAI Responses 或 Anthropic Messages；与 API 地址对应。      |
| API 密钥                     | 对应服务的访问凭据。在 DSH 凭据界面填写，不放进 Bot 的人格文本或聊天消息。                         |
| 获取可用模型                 | 从服务获取模型目录；能否获取取决于接口支持与凭据。获取失败时可手动添加服务商给出的模型 ID。        |
| 模型 ID                      | 请求中发送的真实模型标识，必须与服务商一致。                                                       |
| 模型显示名称                 | 选择器中的友好名称，不改变模型 ID。                                                                |
| 模型选项 → 上下文窗口        | 模型的上下文容量；按服务规格填写，可使用界面支持的 `256K` 这类格式。                               |
| 模型选项 → 最大输出 token 数 | 单次输出上限的模型规格，如 `32K`。不是每次必然输出的长度。                                         |
| 模型选项 → 输入类型          | 文本为必选；只有模型实际支持图片时才勾选图片。                                                     |

![自定义 API 表单与单个模型的选项](/guides/settings/model-provider-custom-zh.webp)

内置目录的 **自定义设置** 可以覆盖 API 地址和模型目录。没有目录条目时，DSH 提示模型选择器不会显示模型；Bot 的模型预设也需要可用目录条目。不要只保存 Provider 后就结束配置。

## 2. 打开要配置的 Bot

关闭设置，进入 **Bot 模式**，打开目标 Bot 的私聊。点击聊天顶部的 **Bot 名称 / 头像 → 查看详细**，进入 PersonaBot Profile，向下找到并展开 **模型预设**。

![从聊天顶部进入 PersonaBot Profile，再点击查看详细](/guides/settings/model-profile-entry-zh.webp)

这里配置的是这个 Bot。左侧 **Bot 设置** 中的图标、排序和并发上限是全局选项；DSH 的 **Agent 预设** 选择工具和工作方式，也不是 Bot 的模型预设。

## 3. 创建并应用模型预设

首次配置时，在 **创建新预设** 中填写名称，选择两种模型及各自的 Reasoning effort，然后点击 **创建并应用**。

| 参数                | 用途                                                                                                    |
| ------------------- | ------------------------------------------------------------------------------------------------------- |
| 预设名称            | 可复用的模型组合名称，例如「日常助手」。                                                                |
| Orchestrator 模型   | Bot 接收消息、协调工作和日常对话所用的模型。                                                            |
| Assignment 默认模型 | Bot 创建新任务执行会话时，未另选模型所使用的默认项。                                                    |
| Reasoning effort    | 模型支持的推理档位；选项来自对应模型。选择「模型默认 effort」不强制指定档位。不同模型不一定有相同选项。 |
| 创建并应用          | 同时保存预设，并为当前 Bot 保存一份独立模型快照。                                                       |
| 快速切换预设 → 切换 | 将已保存预设应用到当前 Bot；仅选择下拉项还没有应用。                                                    |

![应用后显示此 Bot 的独立快照，以及 Orchestrator 与 Assignment 模型](/guides/settings/model-bot-preset-zh.webp)

成功后检查 **此 Bot 当前的独立快照**：应显示期望的 `Provider ID / 模型 ID / effort`。不同 Bot 可以应用同一预设，也可以用不同组合。

## 4. 调整单个 Bot 与任务模型范围

应用过预设后，还有这些控件：

| 操作                                          | 生效范围                                                                           |
| --------------------------------------------- | ---------------------------------------------------------------------------------- |
| 编辑所选预设 → 保存预设修订                   | 更新模板，供今后应用。已有 Bot 的独立快照不变；需要更新的 Bot 要再次切换到该预设。 |
| 仅为此 Bot 修改 Orchestrator → 保存自定义快照 | 只修改当前 Bot 的对话模型与 effort，成为自定义快照；不修改共享模板。               |
| Assignment 可选模型                           | 勾选当前 Bot 创建新任务时允许选择的模型，至少保留一个。                            |
| 允许的 effort                                 | 为每个允许模型保留至少一个推理档位。                                               |
| 此模型的默认 effort                           | 从该模型允许的档位中选择默认项。                                                   |
| Assignment 默认模型                           | 从已勾选模型中选择未指定模型时使用的默认项。                                       |
| 保存 Assignment 模型范围                      | 保存上述范围；新任务只能选择范围内的模型与 effort。                                |

任务模型选择在创建任务时确定。调整默认值不等于重配已创建的 Assignment。Bot 正在生成的回复也不会因保存而重新执行。

## 5. 验证实际使用的模型

返回聊天，发送一句简短消息。收到回复后，在 Profile 的 **Token 用量** 按模型或提供商查看新用量；需要核对具体会话时，从右侧 **会话** 打开对应的 DSH Session，检查其模型选择器和下一轮的用量记录。

![实际 Session 中的 DeepSeek Flash / High 选择器与应用预设后的回复](/guides/settings/model-session-verification-zh.webp)

Profile 的模型快照与已打开 Session 的模型选择是两个可见状态。对于恢复的会话，保存后应核对下一轮实际使用的模型；本教程不把一个已保存标签当作请求验证。运行中的任务需要在对应会话中检查。

| 问题                         | 检查步骤                                                                              |
| ---------------------------- | ------------------------------------------------------------------------------------- |
| 「没有可用模型」             | 回到设置 → 模型，确认 Provider 已保存、凭据可用、模型目录有条目，再重新展开模型预设。 |
| 「当前模型不可用」或需要修复 | Provider/模型可能已删除或改名；为 Bot 重新选择并应用一个有效预设。                    |
| 编辑模板后 Bot 没变化        | 模板修订不会修改已有快照；在目标 Bot 上再次点击「切换」。                             |
| 没回复 / 服务报错            | 核对 Provider 的地址、协议、密钥、模型 ID 和服务额度；先完成本地 DM 验证。            |
| 实际会话模型与快照不一致     | 检查对应 Session 的模型选择与下一轮用量，保留结果用于反馈；不要仅重复改模板。         |

其他参数和入口见 [设置指南](/zh/docs/settings)。IM 连接见 [Lark / 飞书](/zh/docs/lark-connection) 与 [Slack](/zh/docs/slack-connection)。
