## 2. 分仓库说明（逐个交代构建、slot、通信、样式与坑）

### 2.1 R1 miuzel/dsh-subagent-ui — 手写构建流水线的极致

- **构建（重点）**：无打包器。`scripts/build.mjs:14-31` 维护一份**手工的模块拼接顺序**（注释警告「Do not reorder: cross-module references resolve by scope position at runtime」），sucrase 只做类型擦除（`disableESTransforms: true`，`build.mjs:60`），再删相对 import 行、删 `export ` 前缀，最后包 `window.__ModuleLoader__.load` 头尾（`:34-38`）。`verify-build.mjs` 用历史 golden（v1.3.4 手写 bundle）做 token/行级对比，证明迁移无行为变化；`verify-fresh.mjs` 防「改了 src 忘了重编 lib」。工程纪律强，心智负担高。
- **slots**：只注册 `conversation.session.header.actions`（`src/client/apply.ts:4`），模块 `inject:['sessions','slots','locale']`；管理面板本体是自绘浮层，不走 slot。
- **RPC/数据**：删除走 `fetch('/api/dsh-subagent-workspace-ui/delete|batch-delete')`；host 半 `lib/index.js:226-296` 用 `ctx.inject(['webServer'], …)` 运行时注册路由（可选依赖不阻塞挂载，好模式），但**直接扫描并 `fs.rmSync` `$DSH_HOME/sessions` 目录**删除会话（`:44-58`），与宿主存储布局强耦合，高风险（见 §6）。
- **其余**：模板字符串样式 + token；i18n zh/en；无单测/CI；`AGENTS.md` 规定完整 dev 分支/验证/发布节奏，README 双语气质最好的一批。

### 2.2 R2 DSH-EasyRewrite — 单文件 616KB 的「模板烘烤」

- **构建**：`build.mjs` 只做一件事：读 `assets/edit.png`/`recall.png` → base64 → 替换 `src/client.src.js` 占位符 → 写 `lib/client.js`（`build.mjs:1-18`；`wc -c` = 615,967 字节）。真正的源码是 4272 行 `client.src.js`（React.createElement、无 JSX/TS）；`lib/client.js` 提交且 `prepare/prepack` 重跑，属「预构建提交但可复现」。
- **slots**：`conversation.chat.node`（key `user`、priority -1 抢占用户气泡）、`conversation.input.dock`、`conversation.chat.assistant-actions`、`settings.plugin.item`（`client.src.js:4106-4260`）。
- **风险点**：`settings.plugin.item` 在 alpha.2 已删除（官方 `ui-plugin-manager/src/client/slot-contract.ts:32` 现为 `plugins.item`；rewind 的 `docs/compat/audit.md` 明确记录这次删除）。由于 `slots.inject` 是「等声明」语义，设置卡片在新宿主上**静默不渲染**——客户端调研 §8.2 的失败姿态里这正是典型「UI 不出现但无报错」。
- **RPC/数据**：全自定义 `fetch('/bubble/*')`（recall/backup/check-update/update-plugin…），host 日志写 `$DSH_HOME/dsh-easyrewrite.log`；客户端大量 DOM 查询；自带 `MIN_DSH_VERSION`/`MAX_TESTED_DSH_VERSION` 提示 UI（`client.src.js:2322-2335`），对宿主漂移有防御。
- **其余**：内联样式 + token；i18n 空 register + 自管三语；3 个 node 冒烟；README 三语 + `DESIGN.md` + 多轮 review 报告；无 CI。

### 2.3 R3 dsh-rewind — 全样本工程纪律最佳

- **构建（重点）**：`scripts/build.mjs` 是自建构建参考实现：对 client 源做 sha256 得 `buildHash` 注入运行期（`:44-52,94`，识别浏览器里的陈旧 bundle）；`tsc` 出声明；esbuild 出 host ESM 与 client CJS（React/react-dom/jsx-runtime/primitives 外置，`:81-97`）；手工包 loader 头尾（`:100-114`）；最后一长串 smoke 断言（wrapper/id/defines/公开导出/声明文件，`:116-140`），并显式拦截静态 import 已被 0.1.2 删除的 `settingsNamespace`（`:121-128`）。
- **slots/RPC**：`conversation.session.header.actions` 注册「只渲染 portal、不渲染头部 UI」的桥（`src/client/index.ts:248-258`）；配置卡片经 **nested** `ctx.inject(['settingsScope'], …)` 注册进 `plugins.bundle.config`（key=包名，`:280-330`）——故意不把 `settingsScope` 写进模块级 inject，否则没有该服务的宿主会让整个插件不挂载（`docs/compat/audit.md` 有实测记录）。客户端零自定义 RPC。
- **测试/CI**：35 个测试；`tests/client-contract.test.ts:34-52` 用 `readonly (keyof SlotMap)[]` **编译期锁定 slot key**（正是为捕获 alpha.2 删除 `settings.plugin.item` 这类静默失效）；`docs/compat/audit.md` 是「tests are the audit」台账（单一版本线 + I1–I8 不变量 + 每条 seam 的 pin）。CI matrix Node 22/24；publish 用 npm OIDC（无 token）。
- **其余**：模板样式 + token；README 双语 + ARCHITECTURE/SECURITY/CONTRIBUTING；`dsh.engines.dsh` 是 12 家**唯一**声明者。

### 2.4 R4 dsh-compass — 仓库外复刻官方 preset 的范本

- **构建（重点）**：`tsdown.config.ts` 注释自述是「the out-of-tree replication of the fork's packages/client/tsdown.client.ts preset」：host ESM（`external: [/^@deepseek-ai\//]`）；client CJS（`CLIENT_EXTERNALS` 白名单含 `dsh-client-runtime/client` 等共享表项、`noExternal` 兜底内联、env define、banner/footer/intro、`entryFileNames:'client.js'`）；自带 `cssModulesPlugin()`：lightningcss hash 类名 + 每 stylesheet 一次幂等 `<style data-plugin data-plugin-css>`（`:48-79`）。`prepare: tsdown` 保证 git 安装即构建。
- **slots**：主面板放 `shell.overlay`（注释解释「additive by id，且是自带 surface 的官方座位」）；`declare module SlotMap` 自声明子槽 `panel.header.utilities`（`src/client/index.ts:32-41,85-143`）。
- **RPC/数据**：host 半把 git 后端与目录路由做成两个 Cordis child 插件（`src/index.ts:20-72`）；client 用插件自有路由 `fetch('/dir/*','/git/*')`；导出复用官方 `/api/session.export` + `command/executed` 事件。

## 5. 最佳实践候选（附证据与理由）

1. **构建后 smoke 断言 + 运行期 build hash**（R3）。`dsh-rewind/scripts/build.mjs:116-140` 在写盘后断言 wrapper/id/defines/公开导出/声明文件全部成立，失败即构建失败；`:44-52` 把源码 hash 注入 bundle，页面日志可确认「跑的是哪个 commit」。**为什么好**：预览期产物契约（lazy-CJS、head/footer）是最容易悄悄坏掉的地方，把契约变成构建门比人肉 review 可靠。
2. **SlotMap 编译期锁 + 注册清单测试**（R3）。`tests/client-contract.test.ts:34-52` 用 `readonly (keyof SlotMap)[]` 把注册的 slot key 变成编译期契约，并用运行时断言钉住清单；注释直接点名它捕获了 `settings.plugin.item` 被删除的静默失效。**为什么好**：`slots.inject` 对未声明槽位是「无限等待」，没有报错，编译期锁是唯一能自动发现的机制（R2 缺的就是这个）。
3. **tests-as-audit 的兼容性台账**（R3）。`docs/compat/audit.md` 把目标版本、每条 seam、以及 I1–I8 不变量和对应 probe 写在一起，先声明「只支持一条版本线」，再用测试逐条 pin。**为什么好**：DSH 预览期 API 漂移是最大风险；把「我们验证过什么」写成可执行文档，升级时只需重跑 probe。
4. **自包含 tsdown 配置 = 仓库外可复现的官方 preset 等价物**（R4、R11；R7 的简化版）。R4 `tsdown.config.ts:31-79` 把 externals 白名单、`noExternal` 兜底、CSS Modules 注入、banner/footer/intro 全部显式写出，注释说明是官方 preset 的 out-of-tree 复刻；R11 顶部注释直接写「prepare 不依赖旁边存在 harness checkout」。**为什么好**：官方 cookbook 明说没有已发布 preset，外部包必须自己复刻；这两个配置就是可直接抄的答案，且顺带解决 git 安装构建。
5. **nested `ctx.inject` 保护可选面**（R3；R10、R1 是 host 侧同款）。R3 把 `settingsScope` 放进 `clientCtx.inject(['settingsScope'], …)` 而不是模块级 inject，`docs/compat/audit.md` 写明：放模块级会让没有该服务的宿主整个插件不挂载。R10 的 `inject:['typert'] + ctx.inject(['tools'])` 把同样的坑写成 regression lock 测试。**为什么好**：Cordis 的 inject 是「等待」语义，把可选依赖放错位置 = 静默失去核心功能；宿主可选的 webServer/connection 同理（R1 host 的 `ctx.inject(['webServer'], …)`）。
6. **扩展点服务化 + 子槽声明**（R4、R7；官方 ui-plugin-manager 已有先例）。R4 `declare module '@deepseek-ai/dsh-client-ui-slots' { interface SlotMap { 'panel.header.utilities': … } }` 自声明子槽（`src/client/index.ts:32-41`）；R7 用 `ctx.reflect.provide('fileExplorer', …)` 供预览器插件注册。**为什么好**：插件组合是生态的主要增值方式（R7 README 的独立预览器插件），官方 slot 不够用时，声明合并/服务提供是比 DOM 注入可控得多的接口。
7. **真实宿主安装 + 浏览器冒烟的 CI**（R11；R12 是仓内近似物）。R11 `.github/workflows/ci.yml:46-89` 装官方 `dsh@0.1.5-rc.1`、跑 `smoke:install` + Playwright `smoke:browser`，还单开 `exact-github-revision` job 对 push 的 SHA 做 `github:` 安装验证；R12 CI clone 指定 harness tag 后构建再跑 57 测试。**为什么好**：它验证的正是用户实际安装路径（git 安装 + prepare + profile 装载），能拦住「本地测试全绿、装出来是坏的」这类问题。
8. **显式错误边界 + 重连刷新**（R11）。`SlotErrorBoundary.tsx` 包住设置页/RunCenter/Composer，崩溃文案强调「主界面仍可用」；`refreshAgentTeamsOnReconnect(controller, connection.generation)` 在连接代际变化后重读 durable 数据（`src/client/index.ts:41-45`）。**为什么好**：第三方 UI 崩溃不应把官方 shell 拖下水；宿主的 `onEntryError` 之外，自带边界是最直接的保险。
9. **可验证的「无打包器」构建**（R1）。`scripts/build.mjs` 的手工拼接 + `verify-build.mjs` 与历史 golden 做 token/行级对比 + `verify-fresh.mjs` 防 stale lib。**为什么好**：给出了一条不引入打包器的合规路线，且用 golden diff 把「重构前后等价」变成机器可验证的事实；代价（模块顺序即语义）也在 README/AGENTS 里写清。
10. **不变量优先的「不做兜底」**（R5 的自我诚实 + R3 的单一 channel）。R5 README 明说「锚定失败就不注入任何视图，不保留形同虚设的降级」，并删掉不可达的 footer 浮层；R3 删除所有旧版本兼容分支，只读目标版本的 shape。**为什么好**：预览期最贵的是维护幽灵代码；把「不支持什么」写清楚比假装兼容更工程化。
11. **Fork 治理与数据位置**（R10）。`CUSTOM-FORK.md` 定义 main/dev 分支角色、`scripts/sync-to-install.cjs` 一键重放、数据目录固定在 `<profile>/data/task-notify`（重装/改名不丢）、回归锁测试（`test/host.test.mjs`）。**为什么好**：fork 是社区事实（许多插件是改上游产物），把「安装物会被重装覆盖」「数据要在 node_modules 外」这些坑显式化，是对用户负责。
12. **清单扩展字段做「来源披露」**（R10）。`dsh.inventory`（双语标题/描述）+ `dsh.origin`（upstream/fork/note）是样本中唯一使用这两个字段的仓库。**为什么好**：对插件市场（R8/R9 这类）和用户审计都直接有用；其他 11 家都没用，属于未被利用的官方能力（官方 client 调研 §2.1 未列这两字段，说明是较新的清单扩展——未验证官方扫描器行为）。

## 8. 对 BotHarness 的落点

> 前提：BotHarness M3 的 `@botharness/client` 是独立包 + 自建构建（ADR-0023、官方 client 调研 §9.3）。以下建议按「直接照抄 / 改造 / 避免」三级给出。

1. **构建（直接照抄 R4/R11 + R3 的验证层）**：以 dsh-compass 的 `tsdown.config.ts` 为模板（双 config、externals 白名单、`noExternal` 兜底、banner/footer/intro、CSS Modules 注入可选），加 dsh-rewind 的 build hash + 构建后 smoke 断言，并写一个 BotHarness 版 SlotMap/注册清单测试（BP2）。不要采用 R12 的「依赖 harness checkout」构建，也不要把 R6/R8 式仓库外路径引用带进来。
2. **发布形态（R3/R11 式）**：`lib/` 不进 git，`prepare`/`prepack` 构建 + `files` 白名单；M3.5 安装门里加一条「git/tarball 安装后 `lib/client.js` 存在且自注册」检查（与 rewind 的 build smoke 同型）。
3. **slot 选择（沿用官方调研 §9.1）**：roster 面 `sidebar.panellist`(id) + `main`(keyed) additive；会话内动作 `conversation.session.header.actions`；设置卡 `settings.section`/`plugins.bundle.config`（key=包名）。**不要**学 R12 的 priority 遮蔽，除非 M4 明确要「Bot 主界面」；也**不要**学 R2 用 `settings.plugin.item`（已删除）。
4. **RPC（R10/R11 实证路线）**：host 用 `ctx.connection.rpc.intercept('/api', …)`（或 `fetch.register` 精确路由），方法名 `botharness/<method>`，信封用官方 `ConnectionRpcResult`；client 统一封装一个 `call()` 并把 `result.ok` 检查做成类型守卫（R8/GUI 的错误处理形态）。这与 `docs/client-bridge.md` 的决策一致，且本样本证明该路线在社区可用（R10 的 `taskNotify/*`、R11 的 `agentTeamGui`）。
5. **可选服务显式化（R3/R10/R1 教训）**：`settingsScope`、`connection`、`webServer`、`timer` 之类可能缺席的服务一律放 nested `ctx.inject([...])` 或 host 侧 runtime `ctx.inject`；模块级 inject 只放 `slots`/`sessions`/`locale` 这类基线。
6. **数据来源**：优先 `ctx.sessions`/`ctx.workspaces`/标准 hooks（R3/R6/R7/R12 实证）；PersonaBot roster 的运行态若要实时，先做低频轮询（R10 的 `pullSince` cursor 模式可抄）而不是自建 SSE；导入/导出、文件类操作走 host 自有路由 + `connection.fetch.register`。
7. **样式与 i18n**：CSS Modules（若构建管线支持）或字符串 + `<style data-plugin>`；只用 `--dsw-*` token（R1/R3/R4/R7/R9/R11 一致）；i18n `ctx.locale.register(NS, {zh,en})` + `locale: NS` 注册参数，文案进 typed 字典（与官方调研 §9.3 一致）。
8. **测试与 CI**：最低配 = 逻辑测试 + 契约锁 + `build` 门（R3/R4）；高配 = 组件测试（R6/R7/R11/R12 自搭 jsdom）+ 真实宿主安装冒烟（R11）。M3.5 gate 可直接借鉴 R11 的 `exact-github-revision` 思路：对 PR 的 SHA 做一次 `github:` 安装 + 启动冒烟。
9. **清单元数据**：`dsh.engines.dsh` 与 peer 区间双声明（R3 是唯一范例）；`dsh.inventory`/`dsh.origin`（R10）值得 BotHarness 在 registry（M7）用上，用于披露 fork/来源。
10. **避免清单**：DOM 锚点/类名选择器（R5）、自挂 `document.body` 不用 slots（R7）、宿主文件布局直读写（R1）、单文件 600KB 预构建（R2）、lib 即源码（R5/R10）、无 LICENSE/无 CI 发布（R5/R6/R8）。

## 9. 未验证 / 存疑

1. **未运行验证**：所有 slot 渲染、RPC 往返、Typert remote、构建产物被宿主接受与否均未实测；本调研只读源码/配置。R3/R11/R12 的 CI 通过了它们自己的断言，不代表在本机/当前宿主可用。
2. **`slots.inject` 未声明槽位的行为**：推断为「等待、不报错」（官方语义 + R3 注释「neither `slots.inject` (waits forever) nor a structural cast reported it」直接佐证）；但 R2 设置卡在 alpha.2 上是否真的静默消失未实测。
3. **R8 的 `remote.pluginInventory`**：已确认官方 `ui-settings-plugin-inventory` 会注入同名 remote（官方源码），但「官方 composition 默认是否包含该插件、其他 DSH 版本是否提供」未验证；plugin-store 的 `lib/client.js` 是否与 `src/index.tsx` 同代未 diff。
4. **R6 的 `lib/` 与 `src/` 一致性**：未做逐字节/依赖图 diff；其 README 声称预构建即发布物，无法确认与官方 `packages/client/ui-side-tasks` 的哪个提交对应。
5. **R1 删除会话的实际副作用**：未验证 `fs.rmSync($DSH_HOME/sessions/...)` 与宿主 session 索引（`workspaces`/`session.list`）是否会产生悬空引用；仅确认代码路径。
6. **E4 类宿主文件读取的稳定性**：R5 读 `~/.dsh-qqbot/model-prefs.json`、R2/R1 直接使用 `$DSH_HOME` 文件，这些路径不在官方公开契约里（官方调研未列），宿主布局变更即坏。
7. **非官方客户端服务**：`reflect`、`timer`、`commandUi`、`modelDirectories` 的稳定性/版本语义未在官方文档中核实；R7/R10/R3/R2 依赖它们工作。
8. **许可证元数据差异**：R5 package.json=MIT 但无 LICENSE 文件（GitHub=NONE）、R6 MIT 但无 LICENSE 文件、R8 有 LICENSE 且 13 open issues；市场类插件是否校验 LICENSE 文件而非 package.json 字段未验证。
9. **构建路线的长期成本**：R12 的 checkout 构建与 R1 的手工拼接都有明显维护成本，但「哪条路线在宿主连续 3 个大版本后仍能 build」无法从快照判断；R3 的单一版本线策略牺牲了兼容面换取可验证性。
10. **样本选择偏差**：本批为指定样本（含 star 0 的小仓库），并非生态随机抽样；社区更大盘的面貌见 `docs/research/2026-09-19-dsh-community-plugins-survey.md`。并行深潜 agent 的旗舰插件结论可能与本文的横向结论互补。
