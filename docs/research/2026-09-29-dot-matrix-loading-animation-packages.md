## 1. 现状基线：我们到底缺什么（先量清楚再谈选型）

### 1.1 原型现状（`prototype/avatar-hair/app.js`）

- `thinking` 态今天就是**三个脉动圆点**：`DOT_X = [-0.557, -0.013, 0.532]`、`DOT_R = 0.165`、`DOT_PEAK = 1.25`（`app.js:414-416`），`dotPulse(t, index)` 是 1.5s 周期的半余弦相位偏移（`app.js:418-422`），三点的相位差 0.5（`app.js:419`）。
- `thinking` 的 `baseBody: false`（`app.js:498`），`hairOnAnim` 默认 `'hide'`（`app.js:1117`）→ **进入 thinking 时头发被整体隐藏，只剩裸点**（`app.js:1208-1212` 的 `hairEverywhere` 门控）。这正是用户想替换的那块。
- `burst` 态已经是**粒子簇**：`burstParticles(t)` 5 个粒子，`rho` 按 `0.75^(10u)` 衰减 + 角度 `u*100°` 旋转（`app.js:431-447`）——即**粒子系统手写版约 17 行**。
- 现有架构已经很适合塞点阵：`STATES` 每个态是纯函数 `pose(t) → { sil, dots, eyeAlpha }`（`app.js:467-534`），`sample → frame → innerHTML` 的绘制路径（`app.js:1195-1209`）已经能吃任意数量的 dot（`paintAvatar` 遍历 `frame.dots`）。**点阵只是把 `dots[]` 从 3 个变成 49 个、把 `dotPulse` 换成一个空间场函数**。
- 体量基线：`app.js` **75,975 B**，`index.html` 8,704 B，头注释明写 `No build, no deps`（`index.html:16`）。**依赖成本 = 0 字节**。

### 1.2 产品现状（`packages/client`）——「很多 Agent state」这句话需要修正

- 我们**已经有**一套 agent 状态词表，5 态：`thinking | working | waiting | blocked | idle`（`packages/client/src/client/labels.ts:3`），映射到 DSH `StateDotState`：`thinking→ongoing`、`working→done`、`waiting→warning`、`blocked→error`、`idle→idle`（`labels.ts:25-31`）。
- 也就是说**只有 `thinking` 一个态是「loading」**，另外四态是**语义状态色**（绿/琥珀/红/中性灰），**语义上不能换成动效**——`waiting`/`blocked` 需要一个持续可读的静态颜色，不是点阵。**「很多 Agent state 用点阵」在已发布的产品面里目前只有 1 个落点**（分析，基于 `labels.ts:25-31` 的映射）。
- token 通道已通：`styles.ts` 走 `--bh-*` → `--dsw-*` 别名（`packages/client/src/client/styles.ts:8-28`），深色覆盖在 `body[data-ds-dark-theme]`（ADR-0028）。**任何点阵墨色都应走同一条 `--bh-*` 别名**，这是 ADR-0028 的既有契约。

### 1.3 DSH shell 已经有一个「进行中」指示器（这是最容易被忽略的基线）

- `ui-primitives` 的 `StateDot` 状态词表 = `done | warning | ongoing | error | idle`，`ongoing` 专指 loading（`@deepseek-ai/dsh-client-ui-primitives@0.2.0-rc.1` `lib/types/StateDot.d.ts`）。
- `state="ongoing"` 渲染的不是点阵而是 **SVG 双圆弧 spinner**：`viewBox 0 0 24 24`，`track` r=9.5 opacity 0.25 + `arc` r=9.5 `stroke-dasharray: 12 150`，**默认边长 14px**（同包 `lib/index.js` 的 `StateDot()`：`const edge = size ?? (state === "ongoing" ? 14 : 10)`；`lib/StateDot.module.css`）。
- 该 CSS 里有一条对我们直接相关的设计意图（原文注释）：「Both animations share one 1.5s period **so pinning their start times aligns them together**」——**DSH 明确把「多实例相位对齐」当作原生要求**，并且实现了 `prefers-reduced-motion: reduce` 分支（关动画，静态 `stroke-dasharray: 18 150; stroke-dashoffset: -3`）。
- **结论（分析）**：任何点阵方案要进 DSH client，审美与工程契约的靶子已经定了——**相位可对齐、token 驱动、reduced-motion 有静态帧、14–20px 必须可读**。库若不满足这四条，就是降级而不是升级。

**关键发现（分析）**：

1. **「点阵 loading」在 npm 上不是一个品类，是三个被词面切碎的语义**——`dot-matrix` 归给硬件/打印机，`loading` 归给 webpack loader 和 CLI spinner，`braille` 归给终端。**没有任何一个包同时满足「Web + 平面点阵 + agent 状态 + 可外部驱动」**。

3. 反过来，**「点阵渲染」这个能力本身在 2025–2026 才变成一个独立包品类**，且新包几乎全部**先做背景/全屏效果，而不是小指示器**（`dotmote` 自述「Brand-agnostic dotted-matrix glow **background**」、`wavedance` 是「animated dot-grid canvas」、`@tohirr/dotix` 是 dataviz）。**小尺寸 14–64px 的状态指示器没有被任何人当作主场景**——这正好是我们的缺口，也是它只能被手写或被一个 AI-agent 专用包偶然覆盖的原因。

### 2.1 复核补充：这一层**确实存在**高质量实现，但它在 npm 之外，而且**不开源**

用户指认了一个具体的目标物（<https://dotmatrix.zzzzshawn.cloud/>），复核结果如下。**这一节修正 §2 第 1 条的适用范围**：结论「npm 上不存在」仍然成立，但「这一类东西没人做」不成立——存在，只是分发模型不是 npm。

**它是什么（自述，一手核验）**：

- meta description 原文：「Dot Matrix is a React component library of dot matrix loaders—expressive loading primitives you install via the **shadcn registry** and **own as local code**」（<https://dotmatrix.zzzzshawn.cloud/>）
- 分发模型：`components.json` 里注册 `@dotmatrix` registry，然后 `npx shadcn@latest add @dotmatrix/dotm-square-3`（或 `@dotmatrix/all`）把源码**拷进你的仓库**（<https://dotmatrix.zzzzshawn.cloud/getting-started/usage>）
- 定位自述：刻意「不做完整设计框架」，只做 loading primitives，「blend into your existing UI language」（<https://dotmatrix.zzzzshawn.cloud/getting-started/introduction>）
- 作者 <https://x.com/zzzzshawn/>；仓库 <https://github.com/zzzzshawn/matrix>：**614★ / 31 fork / 3 open issues / 最后 push 2026-09-26**（活跃）/ 建于 2026-04-24 / TypeScript（`api.github.com/repos/zzzzshawn/matrix`）
- 站点版本标记 `@dotmatrix - v1.5.0`

**规模与形态（从站点 payload 与 registry JSON 实测）**：共 **90 个 loader**，5 个形态族——`dotm-square-*`（20）、`dotm-circular-*`（20）、`dotm-triangle-*`（20）、`dotm-3x3-*`（20）、`dotm-hex-*`（10）。共用三个内部文件：`dotmatrix-core.tsx`（`DotMatrixBase` + 图案/色板）、`dotmatrix-hooks.tsx`（`useDotMatrixPhases` / `useCyclePhase` / `useSteppedCycle` / `usePrefersReducedMotion`）和 `dotmatrix-loader.css`。

**技术机制（读 registry 源码确认，这是本次调研最有价值的产出）**：

1. **DOM 是一个 CSS grid 的点阵（默认 5×5，见 `MATRIX_SIZE = 5` 与 CSS `grid-template-columns: repeat(5, …)`；另有 `dotm-3x3-*` 族用 3×3），每点一个 `<div class="dmx-dot">`**——不是 canvas，也不是每点一个 SVG 节点。`getMatrix5Layout(size, dotSize, cellPadding)` 算格子与 gap。
2. **动画完全在 CSS 里**：一个 `@keyframes` 只改两件事——`opacity` 与一个自定义属性 `--dmx-bloom-level`（驱动辉光）。JS **每帧不做事**。
3. **「点阵图案」的本质是每点一个 order 变量做 `animation-delay` 偏移**。JS 只在建 DOM 时给每个点算一个整数序号，CSS 用它错开相位：
   ```css
   animation: dmx-spiral-snake calc(var(--dmx-cycle) * var(--dmx-speed)) linear infinite;
   animation-delay: calc(var(--dmx-spiral-order, 0) * 0.04 * var(--dmx-cycle) * var(--dmx-speed));
   ```
   观察到的 order 变量至少有：`--dmx-spiral-order`（螺旋入内）、`--dmx-distance`（到中心距离）、`--dmx-ring-order` / `--dmx-outer-order` / `--dmx-middle-order`（同心环）、`--dmx-col-pos`（列）、`--dmx-path` / `--dmx-snake-order`（对角蛇形）、`--dmx-ripple-ring`。
4. **keyframes 库很小，90 个 loader 是它的小组合**：`dmx-ripple`、`dmx-ripple-3`、`dmx-ripple-echo`、`dmx-center-origin-ripple`、`dmx-collapse`、`dmx-hover-ripple`、`dmx-diagonal-alt-sweep`、`dmx-spiral-snake`、`dmx-diagonal-snake`、`dmx-ring-snake`、`dmx-square9-d1…d6`（`steps()` 逐帧）、`dmx-square6-col-snake`（`steps(5, end)`）、`dmx-circular2-ring`（`steps(12, end)`）。**「LED 追逐」质感来自 `steps()` 而不是关键帧数量。**
5. **两级明暗 + 辉光都由 token 驱动**：`--dmx-opacity-base/mid/peak`（默认 0.16 / 0.32 / 1）+ `--dmx-halo-level` + `--dmx-bloom-level`，全部可用 props 覆盖（`opacityBase/Mid/Peak`、`bloom`、`halo`）。
6. **对外 props（可直接抄思路）**：`size`、`dotSize`、`speed`（写进 `--dmx-speed = 1/speed` 反比缩放）、`color` / `colorPreset`（`solid-theme` 走 `var(--color-dot-on)`，另有 7 个渐变色板）、`pattern`（`diamond|full|outline|rose|cross|rings`）、`dotShape`（`circle|square|diamond|hearts`，心形用 inline-SVG mask）、`muted`、`animated`、`hoverAnimated`、`ariaLabel`。
7. **状态语义只到「相位」这一层**：`DotMatrixPhase = idle | collapse | hoverRipple | loadingRipple`；`idle` 与 reduced-motion 都退化为**静态明暗斜坡**（`opacity: 0.16 + pathNorm * 0.78`）。相位由内部 `useCyclePhase`（自跑 rAF，归一化 0..1）或 `useSteppedCycle`（离散步进）产生。

**许可（这是决定性的一条，一手核验 LICENSE 原文）**：GitHub API 报 `NOASSERTION`，LICENSE 标题为 **"Custom Proprietary License"**：

> Permission is granted to use this software, including in commercial and non-commercial products.
> The following are strictly prohibited without prior written permission from the copyright holder:
>
> 1. Publishing, distributing, or presenting any component from this project as a standalone reusable component, or claiming it as part of another component library or similar reusable component collection.
> 2. Selling, sublicensing, renting, leasing, or otherwise commercializing any component from this project, whether modified or unmodified, as a standalone component offering.

**对我们的含义（判断，不是原文）**：

- ✅ 把它用在**我们自己产品里**是许可允许的（“use … in commercial products”）。
- ❌ 但 BotHarness 是**开源仓库**，而 shadcn registry 的安装方式恰恰是「把源码拷进你的仓库」。把这批文件 commit 进我们的公开 repo，等于 clause 1 所说的「distributing / claiming it as part of another component library」——**这条对我们是禁区**。
- ⚠️ 站点的 meta keywords 里写着 `open source`（<https://dotmatrix.zzzzshawn.cloud/> `<meta name="keywords">`），**与 LICENSE 实际内容矛盾**。这是一个尽调结论：**不要按营销词采信它的开源属性**。
- ✅ **可以合法拿走的是「机制」，不是「代码」**：5×5 grid + 每点 order + `@keyframes` 改 opacity + `steps()` 追逐 + bloom token —— 这套做法本身就是 §5.2 手写基线的同一族，而且**比我们手写的更省**（零 JS 逐帧，浏览器合成器跑 opacity）。

**它比 §5.2 手写基线强在哪、弱在哪（逐条）**：

| 维度                          | 该库（CSS order-delay）                                      | §5.2 手写基线（`sample(size,t,state)`）                    |
| ----------------------------- | ------------------------------------------------------------ | ---------------------------------------------------------- |
| 每帧成本                      | **0 JS**（合成器跑 opacity）                                 | 每帧 49 次求值（实测 0.013 ms/4-up，Node 数字）            |
| 图案数量                      | **90 个已调好的图案**，形态族齐全                            | 5 个 arm（ripple/sweep/phase-wave/double-blink/breathing） |
| **能否被状态机 seek**         | ❌ 相位由内部 rAF 产生；外部只能 `animated={false}` 拿静态帧 | ✅ `t` 由调用者给，可暂停、可回放、可与状态时间轴对齐      |
| reduced-motion                | ✅ 有，且退化为静态斜坡                                      | ✅ 需自己接 `matchMedia`                                   |
| 与 14px DSH `StateDot` 的匹配 | 未见 14px 档（`size` 默认 24/36，站点示例 18px）             | 手写时按 §1.3 的 14px 基线设计                             |
| 许可                          | **专有，禁止入库分发**                                       | 我们自己的代码                                             |
| 依赖                          | React + Tailwind + `components.json`                         | 0                                                          |

**结论（对 §2/§5 的修订）**：§2「npm 上没有这一类包」**维持**；但**「没有可参考的实现」要撤回**。这个库给出了该品类最完整的一次公开实现（90 个图案 + 完整 CSS 机制），它同时也是**最危险的一个**——因为它看起来是开源的、可以一行 `npx shadcn add` 装进来，代价是一旦 commit 就再也退不出去。**因此行动建议不变、理由更强**：

- **不要安装、不要拷贝它的文件**（许可 + 开源仓库）。
- **把它的图案清单当作设计规格来抄**：`docs/prototype/…` 里实现 4–6 个我们真正需要的 arm——螺旋入内（`spiral-order`）、中心涟漪（`distance`）、环追逐（`ring-order` + `steps()`）、列下落（`col-pos` + `steps(5)`）——用 §5.2 已验证的 `sample(size, t, state)` 契约承载，这样它们仍然是**状态驱动、可 seek**，同时在实现层享受「每帧零 JS」的好处（把 order→delay 映射交给 CSS，我们只负责在状态切换时重挂一次 class / 变量）。
- 若将来 DSH client 侧要上 React 组件，**同一套 CSS 可以直接复用**（机制与框架无关），只是相位要改成由我们的状态机传入而不是内部 rAF。

**它到底渲染什么（不是平面网格，是球面点阵）**——9 个态 → 9 个 mode（`STATE_TO_MODE` 本机实测导出值）：

```
working→orbits(轨道粒子)  searching→globe(扫描子午线)  solving→rubik(色带错位)
listening→wave(波形过环)  connecting→web(星座连线)  weaving→braid(三股编织)
composing→ribbon(飘带)   breathing→ring(呼吸环)    shaping→morph(圆→三角→方)
```

**驱动契约（本机实测，这是它最大的优点）**：

```js
// 官方类型：ModeFrame = (size, t, opts) => OrbFrame  — dist/engine/types.d.ts
const frame = MODE_FRAMES[mode];
frame(64, 1.234, opts); // → { dots: [{x,y,z,r,white,a}…], lines: [] }
```

- **纯函数、无闭包、只依赖 `Math`**（`engine/types.d.ts` 原文：「Deliberately closure-free and `Math`-only」）——因此可跑在 RN Reanimated worklet / Swift port 里。
- **确定性实测**：同一 `(size, t, opts)` 两次调用输出**逐字节相同**（`JSON.stringify` 相等 = `true`）。
- **可 seek 实测**：`t=2` 与 `t=3` 输出不同（`true`）。→ **pausable / seekable / 由外部状态机驱动，全部免费得到**，因为时间是我们传进去的标量。
- 官方还暴露逃生口 `frame?: ModeFrame` prop（「replace the state's geometry outright … the painter, theme, tint, pause and offscreen handling all stay the library's」，`dist/types.d.ts`）——**即「用它的渲染管线，画我们自己的平面点阵」是官方支持的路**。
- React wrapper 的时间基是 `performance.now()/1e3 * effSpeed`（`dist/index.es.js:702`）——**全实例共享同一时钟**，`paused` prop 存在（`start()` 在 `paused` 时直接 return，`index.es.js:700-701`），离屏 `IntersectionObserver` + `visibilitychange` 自动停（`index.es.js:715-726`）。**这与 DSH `StateDot.module.css` 注释里「pinning their start times aligns them together」的意图一致。**

读法（分析）：**点半径在整个尺寸区间几乎是常数（0.3–1.5 CSS px），变的是矩阵分辨率和点数**——这正是真 LED 点阵的物理手感。64px 满屏时 `composing` 一帧 566 个 `arc()`，4-up 就是 2264 次/帧。

**三个硬约束（本机实测，必须写进决策）**：

1. **`resolvePreset(state, size)` 只接受 20 / 32 / 64，其它尺寸抛异常**：
   ```
   size= 14 -> THROWS TypeError: Cannot read properties of undefined (reading 'count')
   size= 16 -> THROWS（同上）
   size= 24 -> THROWS   size= 48 -> THROWS   size= 96 -> THROWS
   size= 64 -> OK (speed 3.24, 132 dots)
   ```
   源码可见 `PRESETS[mode][size]` 是一张只有 3 行的表（`dist/index-B8WsUNf5.js:846`，`preset.count` 无 fallback）。**而 DSH `StateDot` 的 `ongoing` 默认边长是 14px**——正好落在抛异常那一侧。绕过办法是**不用 `resolvePreset`**，直接手搓 `opts` 喂 `MODE_FRAMES`（实测任意尺寸可用），但那样就丢掉了作者的全部调音。
   **佐证这不是我读错**：仓库有 3 个重复的未回复 issue 在要同一件事——[#14](https://github.com/Jakubantalik/thinking-orbs/issues/14)、[#15](https://github.com/Jakubantalik/thinking-orbs/issues/15)、[#16](https://github.com/Jakubantalik/thinking-orbs/issues/16)（custom orb size，2026-08-11/15/19）。
2. **`rMin` 下限 0.3 CSS px**：14px 尺寸下最大点直径 = 4.3% of box = **0.6 CSS px**（DPR 2 → 1.2 设备像素）。**物理上小于 ~20px 不可读。**
3. **它不是平面网格，是球面/环面点阵。** `thinking` 语义对应的是 `breathing`（ring），而 `working` 是 `orbits`（倾斜轨道）——**视觉语言是「3D 小星球」，不是「LED 面板」**。这与我们要替换的三个脉动点是**不同的形**，不构成直接替代（分析）。

**主题与 token（本轮实测其机制，不是我们的机制）**：

- `theme: 'auto' | 'dark' | 'light'`。`auto` 三层解析：① 祖先元素 `data-theme` 属性或 `dark`/`light` class（**Tailwind/shadcn 约定**），`MutationObserver` 监听；② 否则 `matchMedia('(prefers-color-scheme: dark)')`；③ SSR 安全（`dist/index.es.js:8-30`）。
- **DSH 用的是 `body[data-ds-dark-theme]` + `--dsw-*` 变量（ADR-0028），两套约定都不匹配。** 可行接缝：读 `getComputedStyle(el).getPropertyValue('--bh-…')` 后把值当 `color` prop 传进去（`color` 接受任意 `#rgb`/`#rrggbb`/`rgb()`，且「depth-shading ramp 保留在 tint 上」）。**注意 `color` 是 prop 不是 CSS，`theme` 变化不 live-watch**（改 token 需要重渲染）——这是真实的小成本。
- `prefers-reduced-motion: reduce` → **静态代表帧 `frame(0.6)`，不启动循环**（`dist/index.es.js:697-700`）。✅ 达标。

**维护风险**：

- 独立仓库 17 commits / **1 contributor**（`api.github.com/repos/Jakubantalik/thinking-orbs/contributors`）。**bus factor = 1**。
- 但**实际开发在 monorepo**（541+ commits，push 至 2026-09-24，0.3.2 由其发布），所以「停更」风险低，**「单点故障」风险高**（作者消失则全线停）。
- 同作者的 `bot-avatars@0.1.1`（18 个 bot 身体 + idle/working/sleeping 三态，MIT，9,458/周）也是同一条线的产品——说明这不是一次性 toy（**分析**）。
- 20 个 open issue 里有 3 个是重复的尺寸请求，1 个是 `#13 Demo not working`。**响应面偏慢**。

**它是什么**：**手写帧序列**驱动的点阵屏。`sequence: number[][]`，每帧是「哪些点亮」的索引数组（`index = row*cols + col`）：

```tsx
const sequence = [[24], [17, 23, 25, 31], [10, 16, 18, 24, 30, 32, 38], [17, 23, 25, 31], [24]];
<DotMatrix sequence={sequence} cols={7} rows={7} />;
```

**不满足我们的地方**（逐条对本 §4 约束）：

- **每个状态要手写 N 帧索引数组**。做一个「convincing 的 agent 状态点阵」，5 态 × 8–12 帧 = 40–60 个手写帧数组，且**插值完全不存在**（离散跳变，`interval` 默认 100ms）。**我们要的是连续的空间场，不是帧表。**
- **React-only**：`import{useState...}from"react"` + `jsx-runtime`。**no-build 页面要用它得先从 CDN 拉 React**，为一个 1.6KB gz 的组件引入两个运行时——不划算。
- **颜色**：`color` / `inactiveColor` 直接进 inline `backgroundColor`，所以传 `var(--bh-…)` **能work** ✅（这是唯一比 `thinking-orbs` 好的地方：天然 token 化）。但只有 **active / inactive 两档**，没有 alpha ramp、没有深度。
- **无 `prefers-reduced-motion`**（源码里没有 `matchMedia`）。
- **DOM 成本**：49 个 div/实例，4-up = 196 个 DOM 节点 + 每帧一次 React setState → 一次 re-render。可用但不是最省。
- **不可 seek 到任意 t**（只能逐帧步进）。

**结论：可作为「帧表式点阵屏」的参考实现读，但不作为依赖引入**（分析）。

### 3.4 其余五类（按任务给的分类 (b)–(f)）

## 5. 结论：hand-roll

### 5.1 为什么不用库

1. **品类不存在**（§2）。不是「没搜到好包」，是**这个尺寸/形态组合（14–64px 平面点阵 + agent 状态 + 外部驱动）在 npm 上无人做**。
2. **唯一够格的 `thinking-orbs` 形态不对且尺寸不对**（§3.1）：它是球面点阵 + 只调 20/32/64px，而我们要替换的正是 DSH 侧 14px 语境下的平面三点。**它是「更好的 64px 头像内指示器」，不是「更好的 loading 点阵」。**
3. **加依赖的固定成本与收益不成比例**：为一个 49 点的动画付 7–15KB gz（`thinking-orbs`）、62–76KB gz（lottie）、102KB gz（rive）、44KB gz（tsparticles），换来的只是「一个 rAF 循环 + 一个时间函数」——而这两样各值 10 行。
4. **依赖税在我们这里有额外成本**：`packages/client` 走 tsdown + `THIRD_PARTY_NOTICES.md` 登记（`packages/client/package.json` 的 `files` 字段），且 ADR-0028 明确「in-harness 不加组件库/第二套设计系统」。**为一张动效付一次依赖审查不划算。**
5. **同族包已给出反面教材**：`ledding`（GPL-3）、`dot-matrix-grid`（CC-BY-SA）、`h5dmd`（LGPL-3）、`p5`（LGPL-2.1）——这一层的**许可污染率明显偏高**（**分析**：因为「点阵」这个词把大量硬件/科学计算库带进来了）。**避开这个生态本身就是许可风险管理。**

### 5.2 推荐的手写基线（**已实现并实测**，非伪码）

**核心思想（这是唯一的算法要点）**：点阵动效不是「时间轴上的姿势」，而是**定义在空间上的一个随时间移动的场**。每个点的幅值 = `arm(distance_to_focal, t)`，`t` 由外部给。这样才可能可 seek / 可暂停 / 可由状态机驱动。

可选的五种 arm（各 ~2 行）：

| arm          | 数学形状                                                          | 读起来像             | 适合状态    |
| ------------ | ----------------------------------------------------------------- | -------------------- | ----------- |
| **径向涟漪** | `0.18 + 0.82·smoothstep(0.55, 0, \|d − p\|)`，`p = (t/1.6) mod 1` | 一圈从中心扩散再收回 | `thinking`  |
| **扫描扫掠** | `0.12 + 0.88·clamp(1−\|d−p\|/0.16) + 0.25·smoothstep(0.34,0,d)`   | 一道光带左→右扫过    | `working`   |
| **相位波**   | `0.2 + 0.8·(0.5+0.5·cos((d − t/0.9)·2π))`                         | 对角波纹滚动         | `streaming` |
| **双闪告警** | `p<0.5 ? 0.25+0.75·smoothstep(0.34,0.24,d) : 0.25`                | 两次硬闪后静止       | `error`     |
| **呼吸地板** | `0.1 + 0.1·sin((t/2.4)·2π)`                                       | 几乎不动的低幅呼吸   | `idle`      |

**参考实现（vanilla JS，111 行，3,651 B / 1,705 B gz —— 本文件 §6 引用的就是它的实测输出）**：

```js
/* Agent-state dot matrix. Pure function of (t, state): no loop, no DOM, no deps. */
const TAU = Math.PI * 2;
const clamp = (x, lo, hi) => Math.min(hi, Math.max(lo, x));
const smooth = (e0, e1, x) => {
  const t = clamp((x - e0) / (e1 - e0), 0, 1);
  return t * t * (3 - 2 * t);
};

/** A square lattice of dots inside a `size`-px box, normalised coords kept. */
export function lattice(size, cols, rows, pad) {
  const step = (size - pad * 2) / (cols - 1),
    dots = [];
  for (let j = 0; j < rows; j++)
    for (let i = 0; i < cols; i++)
      dots.push({ u: i / (cols - 1), v: j / (rows - 1), x: pad + i * step, y: pad + j * step });
  return dots;
}

/* Every arm returns 0..1 for ONE dot. Shared idea: a phase that travels
   through space, so the pattern is a field, not a keyframed pose. */
const ARMS = {
  thinking: (d, t) => {
    const p = (t / 1.6) % 1;
    return 0.18 + 0.82 * smooth(0.55, 0.0, Math.abs(d - p));
  },
  working: (d, t) => {
    const p = (t / 1.15) % 1;
    return 0.12 + 0.88 * clamp(1 - Math.abs(d - p) / 0.16, 0, 1) + 0.25 * smooth(0.34, 0, d);
  },
  streaming: (d, t) => 0.2 + 0.8 * (0.5 + 0.5 * Math.cos((d - t / 0.9) * TAU)),
  error: (d, t) => {
    const p = (t / 1.3) % 1;
    return 0.25 + (p < 0.5 ? 0.75 * smooth(0.34, 0.24, d) : 0);
  },
  idle: (d, t) => 0.1 + 0.1 * Math.sin((t / 2.4) * TAU),
};
export const STATES = Object.keys(ARMS);

/** The whole renderer. `t` is seconds, supplied by the caller — that is what
    makes it pausable, seekable and state-machine-driven. Colours stay in CSS. */
export function sample(size, t, state, opts = {}) {
  const cols = opts.cols ?? 7,
    rows = opts.rows ?? 7,
    pad = opts.pad ?? size * 0.14;
  const rMax = opts.rMax ?? size * 0.052,
    rMin = opts.rMin ?? size * 0.018;
  const arm = ARMS[state] ?? ARMS.idle;
  return lattice(size, cols, rows, pad).map((dot) => {
    const d = Math.hypot(dot.u - (opts.fx ?? 0.5), dot.v - (opts.fy ?? 0.5));
    const k = clamp(arm(d, t), 0, 1);
    return { x: dot.x, y: dot.y, r: rMin + (rMax - rMin) * k, a: 0.25 + 0.75 * k };
  });
}

/** SVG emitter — one <circle> per dot, one CSS class, `currentColor` ink. */
export const toSVG = (dots, cls = 'bh-dot') =>
  dots
    .map(
      (d) =>
        `<circle class="${cls}" cx="${d.x.toFixed(2)}" cy="${d.y.toFixed(2)}" ` +
        `r="${d.r.toFixed(2)}" opacity="${d.a.toFixed(3)}"/>`,
    )
    .join('');

/** Canvas emitter — same fields, zero DOM nodes. */
export function drawCanvas(ctx, dots, ink) {
  ctx.clearRect(0, 0, ctx.canvas.width, ctx.canvas.height);
  ctx.fillStyle = ink;
  for (const d of dots) {
    ctx.globalAlpha = d.a;
    ctx.beginPath();
    ctx.arc(d.x, d.y, d.r, 0, TAU);
    ctx.fill();
  }
  ctx.globalAlpha = 1;
}
```

**接进现有原型（接缝已经在那里了）**：现有 `STATES.thinking.pose(t)` 返回 `{ sil, eyeAlpha, dots }`，`paintAvatar` 已遍历 `frame.dots`（`app.js:1195-1209`）。所以改动是——**用 `sample()` 产出 49 个 dot 替换 `dotPulse` 的 3 个点**，并把 `hairOnAnim` 从 `'hide'` 改成 `'show'`（`app.js:1117` / `1208-1212`）让头发保留、点阵作为覆盖层。**状态机那一侧完全不用动**：`STATES` 已经是 `pose(t)` 的纯函数表（`app.js:467-534`），`sample(size, t, state)` 与它同构。

### 5.4 复核：找到了同类最佳实现之后，结论不变、理由更强

§2.1 找到的 `dotmatrix.zzzzshawn.cloud`（90 个 loader、5×5 CSS grid + 每点 order delay）是这一品类的公开最佳实现，但**专有许可禁止入库分发**（§2.1 许可段）。因此：

- **方案不变**：不装第三方包，走手写 + 零依赖。
- **设计输入变了**：不再自己凭空发明 arm，而是按 §2.1 记录的那套**已被验证的机制**实现——`spiral-order` / `distance` / `ring-order` + `steps()` / `col-pos`，配合 `--dmx-opacity-base/mid/peak` 这样的三级明暗 token 和 bloom 层。图案名字与形态族可以直接沿用（对内是设计语言，不是抄代码）。
- **实现分工变了**：相位**计算**留在我们的 `sample(size, t, state)`（状态机驱动、可 seek），而 order→delay 的错相位**交给 CSS**（`animation-delay` 吃一个我们写进去的自定义属性），从而拿到「每帧零 JS」。切换状态时只重挂一次 class/变量，不进渲染循环。
- **新增一条硬约束**：任何点阵方案进仓库前，先确认它不是这个库（或任何专有/带分发限制的 registry 组件）的拷贝。`docs/research/2026-09-29-dot-matrix-loading-animation-packages.md` §2.1 是这条约束的来源记录。

## 7. 建议的 tracer bullet（下一步）

> **在 `prototype/avatar-hair/` 内把 `thinking` 态从 3 个脉动点换成手写 7×7 空间场点阵，并让它与 `thinking-orbs` engine 的 `breathing` 并排同屏对照；顺带把 `hairOnAnim` 从 `hide` 改成 `show`。**

**范围（刻意收窄）**：

1. 在 `app.js` 里加 §5.2 的 `sample()`（~111 行，零依赖），`STATES.thinking.pose` 改用它产出 49 个 dot；**其余四态（`idle`/`wink`/`burst`）一行不动**。
2. 加一个 `?matrix=off|field|orb` 开关（沿用该原型既有的 `?variant=` 切换惯例，`index.html:8`），让三者在同一页面同屏：
   - `off` = 现状三点（对照基线）
   - `field` = §5.2 手写空间场
   - `orb` = 从 CDN `import('thinking-orbs@0.3.2/dist/engine.es.js')` 的 `MODE_FRAMES.ring`（**同屏对照，用来回答「球面点阵 vs 平面 LED 网格哪个更像 BotHarness」**——这是本轮无法从文档判定的问题）
3. `hairOnAnim` 加第三档 `'field'`：点阵态**保留头发**（修掉今天 thinking 时头发消失的问题）。
4. 墨色走 CSS 变量（`--bh-…` → `var(--dsw-…)`），与 `styles.ts` 的既有别名同构。

**通过判据（全部人工可验收）**：

| #   | 判据                                                                                             | 失败即判负                              |
| --- | ------------------------------------------------------------------------------------------------ | --------------------------------------- |
| ①   | 20 / 32 / 64px 三个尺寸下，7×7 点阵**每个点都清晰可辨**（不是糊成一片），最大点 ≥ 1.5 CSS px     | 不满足 → 手写也要改 `rMax` 或降列数     |
| ②   | 4-up（2×2）布局下 60fps **实测**（记帧率与 CPU 占用；本轮 0.013ms 是 Node 数字，不是浏览器数字） | 不满足 → 换 canvas 发射器（0 DOM 节点） |
| ③   | `prefers-reduced-motion: reduce` 下**动画停在一个有辨识度的静态帧**（不是空白、不是全灭）        | 不满足 → 静态帧选错 `t`                 |
| ④   | 点阵色由**单个 CSS 变量**控制，切换明/暗主题只改这一个变量；`svg` 上零内联色值                   | 不满足 → 违反 ADR-0028，回炉            |
| ⑤   | **人眼评审**：`field` 与 `orb` 二选一，或都不选。`orb` 若被选中，必须能接受它在 20px 以下不可用  | ——                                      |
| ⑥   | 状态机侧零改动：`STATES` 仍是 `pose(t)` 纯函数表，`thinking` 进出仍由既有 `blendPose` 处理       | 不满足 → 说明接入方式错了               |

**不在这片里做的事**（留给判据⑤之后）：不做 `error`/`streaming` 态的点阵（先只换 `thinking`，一个态证明链路）；不做 matrix-rain 列下落 / 呼吸簇的第三、第四种 arm（等评审）；**不引入任何依赖进 `packages/client`**（这一片在 `prototype/`，`index.html` 头注释已声明「Not production. Do not import from here」）。

**判负时怎么办**（预写，避免事后合理化）：

- 若 ① 判负（16–20px 点阵物理不可读）→ 结论落回 **`loading-dots`（1.8KB）或手写 CSS 逐点 `animation-delay`**，「点阵」这个视觉语言在 14px 的 DSH 语境下不成立，直接关票。
- 若 ② 判负 → 换 canvas 发射器（`drawCanvas` 已写好，零改动只换后端）。
- 若 ⑤ 双否 → 关「点阵 loading」这个票，把结论写进 ADR 归档（**不是一个实现决策，是一个「DSH 14px 语境下点阵不成立」的架构结论**）。

## 8. 未验证 / 待确认

1. **`file://` 双击打开时 CDN 跨源 ESM 能否放行**——与 `2026-09-24-threejs-avatar-research.md` §4 同一个未验证项。spike 的 no-build 判据要覆盖。
2. **DSH web client 内的 WebGL/WebGPU 可用性**——本轮不相关（手写与 `thinking-orbs` 都只用 Canvas 2D），但 `h5dmd`（WebGPU）的排除理由部分依赖它。
3. **LottieFiles 上是否存在合格的点阵 lottie 资产及其作者许可**——`lottiefiles.com/page/license` 与 `/api/search` 本轮均 **HTTP 403（Cloudflare）**。许可规则已由帮助中心一手确认（商业可用、无需署名），**资产存在性未验证**。
4. **`public.rive.app` 资源直链 403**（`AccessDenied`），Rive Marketplace 内 `.riv` 的实际体积未验证（不过 102KB gz 的 runtime 已经出局）。
5. **4-up 60fps 在目标机器上的浏览器实测**——§6.3 的 0.013ms 是 Node 数字；§7 判据②就是为了把它变成实测。
6. **blobatar `motion.css` / `gaze.css` 与 `styles.ts` 的合并方式**（`2026-09-19-avatar-and-icon-references.md` §1 的既有未验证项）——若点阵最终并进 avatar motion 层，这条会挡路。
7. **`thinking-orbs` 的球面点阵能否通过 `opts` 覆盖变成平面网格**——`frame` 逃生口是官方支持的，但**「用它渲染我们的平面点阵」这条混合路线本轮未验证**，且会让 dot 颜色退回其 painter 的 ink 模型（丢 token 化）。
8. **brotli 体积**——本文件所有 gz 数字均为 `gzip -9`，未测 brotli（CDN 通常会再省 10–15%，分析）。
