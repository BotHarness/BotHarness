## 用户目标

CLI 应支持无关 UI/UX 的调试与测试场景：在运行中的 Host 创建、配置 PersonaBot，发送消息、读取 Channel 消息并检查执行结果，减少测试对浏览器操作的依赖。

用户同时要求补齐：

- 在线管理：多数现有管理命令应可在 Host 运行时执行。
- 首条链路的创建方式包含空白创建、从 Zip 导入、从 GitHub/Git 仓库导入。不能仅完成空白创建后宣称创建入口已补齐。
- 外部平台完整链路：创建 PersonaBot、授权/发现 App、关联身份、配置会话接收与路由、验证收发；覆盖飞书、微信、Discord、Slack、QQ。
- 现有业务操作的 CLI 入口：Bot 删除与导出、群成员管理、头像等。

这些是需求；首阶段交付顺序、连接选择、失败行为与诊断范围均已确认。后续平台和业务操作仍需按实际切片展开。

## 已确认的第一轮决定

来源：用户在本线程的第一轮回复及随后补充，2026-10-11。

1. **第一条可运行链路**：先在运行中的 Host 创建、配置模型、发送 DM、查询 Channel，再扩展外部平台。用户补充要求创建同时覆盖 Zip 与 GitHub/Git 导入。实施时仍按 tracer bullet 逐个验证创建入口，不一次铺开未经验证的水平层。
2. **测试编排**：业务 CLI 提供操作、权威 JSON 与可恢复回执；独立测试脚本负责组合步骤、断言、隔离与清理。
3. **五平台验收**：每个平台均需真实入站与相应 Bot 回复；先微信，没有真机证据的平台标注待验收。
4. **连接目标**：用户确认 Q2 建议合理，调试/测试主要连接运行中的 Host；第一阶段由 `--host` / `DEEPSEEKBOT_HOST` 显式指定实例。未设置 Host 时保留现有 `--home` 离线操作，仍须取得 writer lease；选定 Host 后连接失败报错，不自动回退写本地 Profile。自动发现不作为首阶段要求。

## 连接方式的解释

用户先询问在线/离线的含义，解释后确认了显式 Host 方案。它们描述 CLI 操作方式，与网络是否连通不同：

- **在线**：CLI 通过认证接口请求正在运行的 DSH Host。Host 持有 Profile 的数据写入权，并负责 Agent、模型调用、调度与 IM 接收。CLI 是另一个操作入口，与浏览器请求相同业务 owner。
- **离线**：没有运行中的 Host 持有该 Profile 时，CLI 直接打开 `--home` 指定的本地数据进行创建、配置等维护。数据写入须取得现有 writer lease；不能借此绕过运行中的 Host。此模式不会运行 Bot 对话和 IM 收发。
- 即使使用离线数据操作，Git 导入仍可能访问网络；反之在线 CLI 也可只连接本机 Host。因此可向 Human 使用“连接运行中的 Host”与“直接维护本地 Profile”说明，避免将 online/offline 理解为互联网状态。

自动发现留作后续便利功能；它需要可靠的实例发现与目标身份确认，不能只从数据库 writer lease 推断接口或认证信息。

Zip 导入将由 CLI 上传本地归档字节，交给 Host 的现有导入 owner；GitHub/Git 导入由目标 Host 获取仓库。这是已核对的生产机制，不等于已完成 CLI 在线适配。Host 使用自身 Git 环境和凭据，不能假定调用者机器上的 Git 登录会自动传递。

## 已确认的第二轮决定

来源：用户在本线程回复“Q5 按推荐 / Q6 按推荐”，2026-10-11。

5. **部分成功后的行为**：Bot 已创建/导入，但模型配置或回复验证失败时保留 Bot、输出已知 ID、已完成阶段与错误，让脚本修正后继续；不自动删除、不盲目重新创建。独立测试脚本只显式清理本轮拥有的临时资源；响应丢失须按 owner 的实际可查询回执/标识区分已完成与未知，不能承诺现有创建接口已具备通用幂等。
6. **首批诊断范围**：先提供 Channel 发现/消息分页、准确关联的回复状态、Bot attention 和 Session 所属/活动摘要；bounded SessionEvent 查询与流式跟随随后补。Session 摘要不能被标作完整工具调用日志；实时草稿也不能被标作持久回复。

首阶段的设计问题已收敛为 [CLI 在线创建与 DM 调试：首阶段规格](2026-10-11-cli-online-dm-scope.md)。用户回复“7 确认”后进入实施；第一条在线空白创建的真实回复及输出反馈提交给用户，用户确认“当前形式可继续”。外部平台 setup 契约与接管、真实验证资源及后续业务操作，在相应 tracer bullet 到来时展开，不提前制造推测性分支。既有产品删除、Bot Zip、群成员与表现设置语义由原 owner 保持，不借 CLI 重新定义它们。
