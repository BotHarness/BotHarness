# AX: local browser permissions and control failures

Use this runbook when a coding agent cannot open, operate or capture an isolated local Web Client. Keep three independent results: **Host transport**, **browser navigation**, and **rendered interaction**. A successful result in one does not certify the others.

## Qualification loop

1. Read the Human's current browser/site authorization and use an explicitly authorized origin. Match scheme, hostname and port: `http://127.0.0.1:4175` and `http://localhost:6701` are distinct origins. A settings screenshot is evidence of the displayed preference, not proof that tool navigation has succeeded. If the origin needs a new permission, ask the Human to authorize that exact destination; reuse authorization already given in this task.
2. Check listener ownership before selecting a port. Use a free authorized port, one isolated `DSH_HOME` and the pinned `scripts/dev-instance.mjs` launcher. When restarting, stop only the verified task-owned PID; keep one Host per home. Treat the port examples below as this machine's evidence, not a repository-wide allowlist.
3. Save the launcher summary privately and verify its authenticated health result. Separately check the actual document route when navigation fails. Record only origin, status and fixed diagnostic codes; login tokens, cookies and raw logs remain machine-local. A direct HTTP probe is transport evidence, never a substitute for a Client click or screenshot.
4. Open the launcher's URL through the selected browser tool, then inspect actual DOM and console evidence. For `ERR_BLOCKED_BY_CLIENT`, record the refusal and route rather than declaring a plugin crash or a missing permission. If server evidence shows a Host admission refusal, use the existing [authenticated fixture navigation procedure](../../.agents/skills/dsh-dev/references/debugging-playbook.md#authenticated-fixture-navigation). Otherwise keep attribution unresolved. Preserve browser and Host security boundaries.
5. For mouse, evaluation or screenshot timeouts, inspect the current page before repeating: the action may already have occurred. Use documented recovery, one bounded fresh-tab retry and, when useful, a single owned tab. Record the exact operation and outcome. Repeated control failures without new evidence end that attempt; reconnecting alone is not a fix.
6. Accept visual qualification only after real actions and saved captures succeed. Match base/PR viewport, locale, theme, representative data and UI state; verify published images load. Preserve earlier successful functional evidence and state the remaining capture gap explicitly. Stop unused owned Hosts and retain reusable builds separately from private Profile evidence.
