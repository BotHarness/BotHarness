Lark 话题下，
其他成员发言会发生什么？

任何群成员都按同一套规则处理。决定收件的是 @谁、群配置、话题配置；决定处理时机的是 Wake Policy。收到之后，PersonaBot 自行判断是否回复。

默认：只收 @Bot。 发过晨报、回复过一次，都不会自动开启话题跟进。其他成员的普通发言默认留在 Lark。

同一个话题，几种常见情况

成员发言 配置 进入 Inbox？ 之后怎样处理
小周普通回复 默认只收 @，未跟进 不进入 仅留在 Lark。不会因这条消息唤醒。
小周 @这一个 Bot 有效授权、收件开启 进入 按 @ 的策略处理；Bot 判断是否回答。
小周 @另一个 Bot 默认只收 @，未跟进 不进入本 Bot 不把 @别人的消息当作 @自己。
小周普通回复 已跟进这个话题 进入 用话题的 Wake Policy；没有覆盖时沿用群策略。
小周普通回复 群开启普通消息收件 进入 用群 Wake Policy；其他话题也按群规则处理。
小周普通回复 话题 exclude，即使群全量 不进入 exclude 只排除普通消息；明确 @本 Bot 仍可进入。

前提：Lark 将合法、支持的消息事件交给当前绑定应用。平台没投递，BotHarness 的规则无法凭空收到消息。

收到之后，怎样关联原晨报？

关联检查发生在收件之后。消息属于同一话题，不代表它一定会被收件；原报告关联也不会改变收件规则。

没有新建本地 Thread 或独立 Bot 会话。 Lark 保留话题与历史。我们保留消息的 threadId／rootId／parentId。已有话题配置表只保存跟进、退出和唤醒规则，不是另一份话题历史。

配置与验证边界

跟进需要先验证普通话题消息能投递。 仅开一个 follow 开关，不会扩大 Lark 应用权限。当前实现会拒绝尚未验证投递能力的话题跟进；Human 可覆盖 Bot 的话题配置。

上下文读取另走授权的按需读取。 默认没收进 Inbox 的消息，如果平台可读，Bot 仍可通过已有群／话题历史工具有界读取。它不是持续自动收件，也不能保证补齐所有历史。

本页按 PR #742 准确 head 的代码解释。真实 E2E 已验证“发报告 → 一个 Human @回复 → 原话题回传”；其他组织成员、多成员并发与所有模拟器组合尚未做新增真实群测试。对应规则有聚焦自动化覆盖。

三个 ID 都来自 Lark，作用各不相同

threadId 标识整个话题；rootId 指向起始消息；parentId 指向这条消息直接回复的对象。Provider 只映射字段名，不生成这三个外部 ID；它们是否存在取决于 Lark 返回的消息类型。

跟进策略按已授权连接与 threadId 查找，并核对群、绑定身份与 rootId。不会要求每条消息的 parentId 都等于根消息。通过收件校验后，再保存 Source Event、创建 Inbox Admission，并按当前策略唤醒。

真实验收中：Human 回复晨报时 rootId 与 parentId 都是晨报 ID；Bot 回复 Human 时 rootId 仍是晨报 ID，parentId 变为 Human 消息 ID。跟进本身不会扩大平台权限；当前普通话题收件要求完整可信的 root/parent 路由。
