- **ADR-0034 — Persistence map**: one home per kind of state. Bot identity/persona/memory stay user-owned files under `$DSH_HOME/botharness/bots/<slug>/` (git-versionable, the M6/M7 package unit); channel metadata and messages stay `…/channels/<id>/{channel.json, messages.ndjson}` with the append-only log authoritative (ADR-0030); the roster arrangement (section membership/names/order, pins) moves host-side into the DSH storage domain `botharness_roster` (`version 1`, `layout: single`, global slot `{ pins, sectionOrder }` + `sections` table keyed by host-generated id); the sort-mode preference (global + per section) moves into the DSH settings namespace `ui-bot-mode` (`settings.yaml`, per-profile, cross-browser), read/written by the client via `ctx.settingsScope.bind({ namespace: 'ui-bot-mode' })` with refresh on the allowlisted `settings/document-updated` event, and additionally exposed as a `settings.general.item` row; only `collapsed` stays in browser localStorage. Derived analytics (unread, counts, search, dashboards) become a rebuildable SQLite index (ADR-0005) — `dsh-storage-sqlite` is not installed today. The client touches none of the host arrangement directly: seven fine-grained bridge methods (`rosterGet`, `sectionCreate`, `sectionRename`, `sectionRemove`, `channelAssign`, `sectionReorder`, `pinsSet`) on the `botharness` typert namespace, action-shaped like `ui-workspace`'s remotes, with section ids returned by `sectionCreate`. Storage is an optional capability (`ctx.inject(['storageDomain'], cb)`); migration is one-way and conservative (host domain empty + legacy `roster.json` present → migrate once, keep the browser key as backup). Realtime is a v1.1 `mode: 'stream'` remote method (roster first, then channel messages); `domain/changed` is in-process only and not forwardable. Caveat: settings writes are memory-only on non-loopback pages (DSH-wide behaviour).
- ADR-0031 update: sections/pins/order move host-side (per the map) and the sort mode moves into `ui-bot-mode` settings; `collapsed` stays local — the SoulSnapshot exclusion still holds. The General settings row adds an entry point and moves no sidebar UI.
- Spec v1.11: §2.1 persistence map (+ directory conventions), §5 sidebar/storage/sort wording + the settings-row entry point, §8 risk rows (arrangement on the Host / non-loopback settings memory-only) and the SQLite-index open item.
